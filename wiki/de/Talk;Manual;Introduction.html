FreeCAD Manual Converter — Fixes für Windows/Python 3.14 (Stand: August 2026)

Das Script auf der Wiki-Seite läuft nicht "out of the box". Hier die Stolpersteine, die mich beim ersten Durchlauf gestoppt haben, plus Lösung. Getestet unter Windows 11, Python 3.14.6.

1. PyPDF2 ist tot

Die Installationsanleitung nennt: 

pip install requests weasyprint beautifulsoup4 PyPDF2 Pillow cairosvg ebooklib

PyPDF2 wird seit 2023 nicht mehr weiterentwickelt. Der Nachfolger heißt pypdf. Wer trotzdem PyPDF2 installiert, bekommt nur die letzte tote Version (3.0.1) — technisch nutzbar, aber ohne jede Wartung/Sicherheitsfixes.

Fix: pypdf statt PyPDF2 installieren: 

pip install requests weasyprint beautifulsoup4 pypdf Pillow cairosvg ebooklib

2. Im Script: PdfMerger existiert in aktuellem pypdf nicht mehr

Das Script importiert: 

from PyPDF2 import PdfMerger

und nutzt PdfMerger() in merge_pdfs(). In pypdf ab Version ~5.0 wurde diese Klasse entfernt — Ersatz ist PdfWriter, das dieselbe .append()/.write()/.close()- API hat.

Fix: Zwei Stellen ändern.

Import (Zeile 6): 

from pypdf import PdfWriter

merge_pdfs()-Methode: 

def merge_pdfs(self, pdf_files, output_file):
    print(f"Merging PDFs into {output_file}...")
    merger = PdfWriter()          # statt PdfMerger()
    for pdf in pdf_files:
        merger.append(pdf)
    merger.write(output_file)
    merger.close()
    print(f"Successfully created {output_file}")

Sonst nichts am Code ändern — die Methodennamen sind identisch geblieben.

3. GTK3-Runtime fehlt (WeasyPrint braucht sie zur Laufzeit)

Die Anleitung erwähnt "GTK3 runtime" als Windows-Abhängigkeit, nennt aber keine Quelle. Ohne sie bricht WeasyPrint beim PDF-Rendern ab (fehlende Pango/Cairo-DLLs).

Fix (am saubersten via winget, da man Updates/Deinstallation dann verwaltet bekommt): 

winget install -e --id tschoonj.GTKForWindows

Danach PowerShell/Terminal neu starten, damit der PATH aktualisiert wird.

Bekannter Zusatz-Stolperstein: WeasyPrint sucht gobject-2.0-0.dll, der Installer legt aber nur libgobject-2.0-0.dll ab (mit lib-Präfix). Führt sonst zu OSError: cannot load library 'gobject-2.0-0'.

Fix: 

Copy-Item "C:\Program Files\GTK3-Runtime Win64\bin\libgobject-2.0-0.dll" `
          "C:\Program Files\GTK3-Runtime Win64\bin\gobject-2.0-0.dll"

Danach den Rechner neu starten (nicht nur die Shell).

Verifizieren, bevor man das Hauptscript startet: 

python -m weasyprint --info

Läuft das ohne OSError, ist die Kette komplett.

Ergebnis

Mit diesen drei Fixes läuft der Converter unter Windows 11 + Python 3.14 sauber durch: 24 Kapitel-PDFs, Inhaltsverzeichnis, gemergtes Gesamt-PDF (172 Seiten bei mir) und EPUB — ohne weitere Fehler.
