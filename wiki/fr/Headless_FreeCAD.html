Introduction

FreeCAD peut être exécuté sans son interface utilisateur graphique (GUI), un mode communément appelé « headless » (sans affichage). Cela offre plusieurs méthodes puissantes pour la création de scripts, l'automatisation et l'intégration de ses capacités dans d'autres applications. Cette page documente les différentes façons d'exécuter FreeCAD en mode headless.

Via la console Python de FreeCAD

Il s'agit d'un mode interactif dans lequel FreeCAD démarre directement dans une console Python. Cette console est un environnement Python entièrement fonctionnel avec tous les modules Python de FreeCAD, tels que Part, BIM et Draft, accessibles via leur API publique. Le module central FreeCAD est intégré, il n'est donc pas nécessaire de l'importer explicitement pendant la session de la console. D'autres modules peuvent être importés pendant la session (par exemple import Part), selon les besoins.

Ce mode peut être lancé à partir de la ligne de commande en utilisant soit FreeCAD -c soit FreeCADCmd. Il offre les mêmes fonctionnalités que la console Python disponible dans l'application FreeCAD complète.

Il est particulièrement adapté pour tester rapidement du code Python qui accède à l'API FreeCAD ou pour déboguer de petits scripts qui peuvent être facilement collés dans la console.

Via un script Python

Dans ce mode, FreeCAD est utilisé comme une bibliothèque Python standard. Cela vous permet d'importer l'intégralité de son API Python dans n'importe quel script ou application Python externe, en le traitant comme un module natif.

Pour cela, l'interpréteur Python doit pouvoir localiser le fichier de la bibliothèque de FreeCAD, FreeCAD.so sous Linux et macOS ou FreeCAD.pyd sur les autres plateformes. Pour ce faire, ajoutez son répertoire aux chemins de recherche de Python au tout début de votre script. Une fois le chemin défini, le reste du script peut accéder à l'API FreeCAD comme n'importe quel autre module Python.

Voici un exemple simple qui crée une boîte et affiche son volume et sa surface : 

# Set the path to your FreeCAD installation
# Example for Linux:
# FREECADPATH = '/usr/lib/freecad/lib'
# Example for macOS:
# FREECADPATH = '/Applications/FreeCAD.app/Contents/Resources/lib'
# Example for Windows:
FREECADPATH = 'C:\\Program Files\\FreeCAD\\bin'
import sys
sys.path.append(FREECADPATH)

# The rest of the script can now import and use the FreeCAD API
import FreeCAD
import Part

# Create a simple geometric shape
my_box = Part.makeBox(10, 20, 30)

# Access its properties
print(f"The volume of the box is: {my_box.Volume}")
print(f"The area of the box is: {my_box.Area}")

Pour exécuter le script d'exemple, enregistrez le code dans un fichier (par exemple, run_box.py) et exécutez-le depuis le terminal de votre système à l'aide de l'interpréteur Python : 

$ python run_box.py
The volume of the box is: 6000.0
The area of the box is: 2200.0

Il s'agit d'une fonction très puissante qui libère tout le potentiel de FreeCAD pour les tâches d'automatisation et d'intégration. Par exemple, on pourrait écrire un script qui exploite à la fois les API FreeCAD et Blender pour importer par programmation des objets depuis un fichier .FCStd directement dans une scène Blender.

Notez que ce mode est destiné à l'utilisation de l'API FreeCAD sans interface graphique. Bien que certains modules liés à l'interface graphique puissent être importés, l'utilisation de l'API qui accède directement ou manipule les composants de l'interface graphique est très limitée et généralement non prise en charge dans un contexte sans interface graphique.

Autres considérations sur les modules des ateliers en mode sans interface graphique

Lorsque l'on utilise FreeCAD en tant que bibliothèque Python dans un environnement sans interface graphique (par exemple via un interpréteur Python standard ou FreeCADCmd), tous les modules des ateliers ne sont pas automatiquement disponibles, même si les modules principaux de FreeCAD peuvent être importés sans problème.

En particulier, les modules situés dans le répertoire Mod/ (tels que PartDesign ou les sous-modules de Part) peuvent ne pas être détectés par Python, à moins que leurs chemins d'accès ne soient explicitement ajoutés à sys.path. Cela peut entraîner des situations où les objets de document sont chargés en tant que types génériques (par exemple GeoFeature) au lieu de leurs types spécifiques (par exemple PartDesign::Body), ou où les importations de modules liés à l'environnement de travail échouent.

Pour garantir un fonctionnement optimal, il peut être nécessaire d'étendre manuellement le chemin de recherche de Python afin d'y inclure le répertoire FreeCAD Mod/ et, dans certains cas, des sous-répertoires spécifiques : 

import sys

# Example paths (adjust to your installation)
sys.path.append("/usr/lib/freecad/Mod")
sys.path.append("/usr/lib/freecad/Mod/Part")

# Workbench modules can now be imported
import PartDesign
from BOPTools import BOPFeatures

Les chemins d'accès exacts dépendent de la plateforme et de la méthode d'installation.

Cette configuration manuelle garantit que les modules des ateliers peuvent être importés, que les objets des documents sont reconstitués avec leurs bons types et que les utilitaires Python supplémentaires fournis avec les ateliers deviennent disponibles.

Remarquez que l'interface graphique de FreeCAD effectue cette initialisation automatiquement. En mode sans interface graphique, cependant, cette étape doit être effectuée explicitement par l'utilisateur.

Exécuter directement du code Python

Les exécutables en ligne de commande de FreeCAD peuvent également fonctionner comme des interpréteurs Python spécialisés, permettant l'exécution directe de code Python. Cela offre une alternative pratique et puissante à l'intégration de FreeCAD dans un script Python externe.

Exécuter un script en ligne

Vous pouvez transmettre une chaîne de code Python directement en tant qu'argument unique. Cela est utile pour les commandes très courtes et à usage unique. Notez que l'argument de ligne de commande ne doit pas être un chemin d'accès à un fichier existant pour que cela fonctionne.

  • Mode headless: l'utilisation de FreeCADCmd exécute le code puis quitte immédiatement. Ce mode est idéal pour les scripts.
$ FreeCADCmd "import Part; print(Part.makeBox(10,5,15).Volume)"
  • Mode interactif: l'utilisation de FreeCAD -c exécute le code puis ouvre une session interactive de console Python. Ceci est utile pour des tests rapides où vous souhaitez inspecter l'état après coup.
$ FreeCAD -c "import Part; my_box = Part.makeBox(10,5,15)"

$ FreeCADCmd "import Part; print(Part.makeBox(10,5,15).Volume)"
  • Interactive Mode: Using FreeCAD -c executes the code and then opens an interactive Python console session. This is useful for quick tests where you may want to inspect the state afterwards.
$ FreeCAD -c "import Part; my_box = Part.makeBox(10,5,15)"

Exécuter un fichier script

Une méthode plus puissante consiste à utiliser FreeCAD pour exécuter directement un fichier script Python. C'est l'approche recommandée pour toute tâche non triviale sans interface graphique. 

$ FreeCADCmd /path/to/my_script.py

Lorsqu'un script est exécuté de cette manière, l'environnement FreeCAD est déjà configuré. L'avantage principal est que le script n'a pas besoin du code standard sys.path.append(). Les modules de FreeCAD sont immédiatement disponibles pour l'importation.

Par exemple, un fichier nommé create_box.py pourrait contenir : {{Code|lang=python|code= import Part

import FreeCAD 

import Part
# The FreeCAD module is already available, but it can be imported explicitly
import FreeCAD

# Create a new document and add a box to it
doc = FreeCAD.newDocument()
box_obj = doc.addObject("Part::Box", "MyBox")
doc.recompute()

# Export the part to a STEP file
Part.export([box_obj], "my_box_model.step")

print("Box created and exported successfully to my_box_model.step")

Running this script from the terminal is as simple as: 

$ FreeCADCmd create_box.py
Box created and exported successfully to my_box_model.step

Via l'application graphique complète sous un écran virtuel

Les méthodes ci-dessus (FreeCADCmd, FreeCAD -c et l'utilisation de FreeCAD en tant que bibliothèque Python intégrée) ne permettent pas de créer des fournisseurs de vue. Si votre script nécessite un accès à ViewObject (par exemple, pour des propriétés telles que le style de texte ou la taille de police), aucune des méthodes ci-dessus ne fonctionnera.

Pour obtenir une session d'interface graphique entièrement initialisée (avec des fournisseurs de vues opérationnels) sans écran physique, sous Linux, vous pouvez exécuter l'exécutable de l'interface graphique FreeCAD sous un serveur X virtuel tel que Xvfb. Contrairement aux modes console, l'exécutable de l'interface graphique effectue son démarrage normal (en créant MainWindow et de véritables fournisseurs de vues).

Sous Linux, cela peut être réalisé à l'aide de xvfb-run, qui se charge automatiquement de l'allocation d'un écran virtuel et du nettoyage : 

$ xvfb-run -a FreeCAD my_script.py

Comme pour l'exécution d'un fichier de script décrite dans Démarrage et configuration, le fichier passé en ligne de commande peut avoir une extension .py ou .FCMacro ; les deux s'exécutent de la même manière.

L'application ne se ferme pas automatiquement une fois le script terminé. Contrairement à FreeCADCmd, l'exécutable de l'interface graphique entre toujours dans la boucle d'événements Qt normale et reste ouvert, que l'écran soit visible ou non pour l'utilisateur. C'est le script lui-même qui doit demander la fermeture.

L'appel de FreeCADGui.getMainWindow().close() seul n'est pas fiable dans ce cas : il suit la séquence interactive normale de fermeture, qui inclut la demande de FreeCAD « Enregistrer les modifications ? » pour tout document comportant des modifications non enregistrées, ce qui bloquera le processus indéfiniment sur un écran virtuel, car une intervention humaine est nécessaire pour fermer cette fenêtre. Effacez d'abord l'indicateur de modification de chaque document afin qu'il n'y ait plus rien à demander : 

import FreeCAD as App
import FreeCADGui as Gui

# ... script code ...

for doc in App.listDocuments().values():
    Gui.getDocument(doc.Name).Modified = False
Gui.getMainWindow().close()

Si, malgré cela, un autre élément maintient le processus actif (par exemple, une autre boîte de dialogue modale sans rapport avec des modifications non enregistrées), un script peut alors recourir à une fermeture forcée qui contourne complètement la boucle d'événements Qt : 

import os
# ... script code ...
os._exit(0)

N'utilisez cette option qu'en dernier recours : elle contourne la procédure normale d'arrêt et de nettoyage de Qt et de FreeCAD, ce qui signifie que tout ce qui serait normalement supprimé lors de l'arrêt (comme les fichiers de verrouillage) reste en place. Privilégiez, dans la mesure du possible, la désactivation de l'indicateur de modification et la fermeture normale du programme.

Exemples

Recherche des modules FreeCAD

  1. Ouvrez le terminal et tapez :
    $ /path/to/FreeCAD -c
    ou
    $ /path/to/FreeCADCmd
  2. Un shell python démarre avec une invite. Tapez help().
  3. Un texte d'aide s'affiche.
  4. Tapez modules freecad.

Représentation du graphe de scène

Comme il n'est pas possible de créer ou d'accéder au fournisseur de vues en mode headless, ce qui est possible, c'est de charger FreeCADGui en mode headless, mais il n'y a aucun moyen d'accéder au document GUI car il ne sera pas créé et, par conséquent, il n'existe aucun fournisseur de vues.

Cependant, il est possible de créer une représentation du Graphe de scène d'un objet : 

import FreeCADGui as Gui
from pivy import coin

Gui.setupWithoutGUI()
doc = App.newDocument()
obj = doc.addObject("Part::Box","Box")
doc.recompute()
view = Gui.subgraphFromObject(obj)
